# Roadmap

Este roadmap representa una dirección de trabajo, no una lista de funcionalidades obligatorias. Las fases futuras deben reevaluarse según el uso real del MVP.

## Fase 0 — Preparación

- Filtrar los inventarios fuente para Barra / Cafetería.
- Construir el catálogo inicial.
- Definir una estructura de proyecto simple.
- Documentar el contexto suficiente para trabajar con Codex.

## Fase 1 — MVP funcional de Barra

Objetivo: disponer de un flujo de inventario que pueda utilizarse y evaluarse.

Incluye el flujo actual de navegación, conteo, estados, notas, responsable, resumen y persistencia local.

El foco es estabilidad y utilidad, no completar toda la taxonomía del catálogo.

## Fase 2 — Refinamiento del MVP

Después de probar la versión funcional:

- revisar categorías;
- revisar nombres y unidades;
- corregir inconsistencias de catálogo;
- ajustar UX según problemas observados;
- decidir qué mejoras realmente aportan valor.

## Posibles evoluciones futuras

Podrían evaluarse, entre otras:

- historial de inventarios;
- stock mínimo;
- otras áreas;
- persistencia remota / backend;
- integración con GetJusto;
- cámara u otras ayudas para el conteo.

Nada de esta sección debe implementarse automáticamente. El uso real del MVP decide qué merece entrar en una fase posterior.

## Regla del roadmap

Cuando una futura funcionalidad compita con la necesidad de mantener simple y funcional el MVP, se debe priorizar primero la validación del flujo actual.
